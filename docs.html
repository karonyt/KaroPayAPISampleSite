KaroPay API

KaroPay は、KaroEarth のゲーム内ドルで支払いを受け付けるサービスです。自分のサイトで「購入」ボタンを押した人を KaroPay の支払いページ（Checkout）へ送り、支払いが終わったら自分のサイトへ戻します。

使い方は 3 つあります。

方法向いている場面認証
サイト用コード版静的サイト（GitHub Pages など）から直接。サーバーが要らない。サイト用コード（公開してよい）
APIキー版自分のサーバーがある。注文の重複防止・取り消しまでしたい。Authorization: Bearer（秘密）
決済リンク決まった商品を URL 1 本で売りたい。コードを書かない。不要

ベース URL: https://karopay.karon.jp。金額の単位はゲーム内ドル（整数）です。

支払いの流れ

  1. 自分のサイトで Checkout を作る（POST /api/checkout/public/sessions）。返ってきた url へ購入者を送る。
  2. 購入者は KaroPay に Karotter か Discord でログインし（Minecraft のアカウントを連携済みであること）、内容を確かめて支払う。
  3. 支払い完了の画面で購入者が「戻る」を押すと、successUrl にクエリ付きで戻る。取りやめたときは cancelUrl へ戻る。
  4. 自分のサイトで状態を読み（GET）、status が paid で、金額と注文番号が合っていれば商品を渡す。
支払いのあと購入者が「戻る」を押さないこともあります。戻ってきたときだけでなく、自分の側で後から状態を読み直せるようにしてください（支払いの確かめ方）。

サイト用コード

サイト用コードは、売上を受け取る KaroPay 口座を表すコードです。KaroPay（karopay.karon.jp/receive）にログインして「受け取り」画面の「サイト用コード」からコピーします。

  • コードで分かるのは「どの口座に払うか」だけです。コードを知っていても、口座からお金を引き出したり、取引を取り消したりはできません。そのため、ページに埋め込んで公開してかまいません。
  • 「再発行」すると前のコードは使えなくなります（CODE_NOT_FOUND）。サイトのコードも差し替えてください。
  • Checkout に表示される受取人名は、コードの持ち主の Minecraft 名です。

Checkout を作る（サイト用コード版）

POST/api/checkout/public/sessions認証なし・CORS 許可

どのサイトからでも fetch で呼べます（Access-Control-Allow-Origin: *）。

const res = await fetch('https://karopay.karon.jp/api/checkout/public/sessions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    receiveCode: 'あなたのサイト用コード',
    amount: 500,
    description: 'VIP Rank',
    clientReferenceId: 'order:12345',
    successUrl: 'https://example.com/success.html',
    cancelUrl: 'https://example.com/',
    expiresInMinutes: 30
  })
});
const data = await res.json();
if (!data.ok) throw new Error(data.error);
location.href = data.url; // KaroPay の支払いページへ

パラメータ（JSON）

名前必須説明
receiveCode必須サイト用コード。receive_code でも可。
amount必須金額。1 以上の整数（上限 100,000,000）。
description支払いページに出す説明。160 文字まで（超えた分は切られる）。
clientReferenceId自分の注文番号。英数字と . _ : - だけ、120 文字まで。戻り先と状態の応答にそのまま返る。client_reference_id でも可。
successUrl支払い完了後の戻り先。http(s) の絶対 URL、500 文字まで。success_url でも可。
cancelUrl取りやめたときの戻り先。条件は successUrl と同じ。cancel_url でも可。
expiresInMinutes支払い期限（分）。既定 30、最大 1440（24 時間）。expires_in_minutes でも可。
modepayment（既定・1 回だけ）か subscription（継続課金）。
subscriptionサブスクのとき { "interval": "month", "intervalCount": 1 }。下を参照。

成功すると 201 で次を返します。

{
  "ok": true,
  "checkoutSession": { "id": "kcs_...", "status": "open", ... },
  "url": "https://karopay.karon.jp/checkout/kcs_..."
}

サブスク（継続課金）

mode: "subscription" にすると、最初の支払いで契約ができ、以後は周期ごとに KaroPay が購入者の口座から自動で請求します。

{
  "receiveCode": "...",
  "amount": 300,
  "description": "VIP Pass（毎月）",
  "mode": "subscription",
  "subscription": { "interval": "month", "intervalCount": 1 }
}
名前説明
intervalday / week / month（daily・weekly・monthly なども可）。
intervalCount1〜12。既定 1。month と 3 なら 3 か月ごと。
  • 次の請求は、前の期間が終わった時点です（最初の支払いから 1 周期後）。
  • 残高が足りないなどで失敗すると past_due になり、およそ 6 時間ごとにやり直します。
  • 購入者は KaroPay の「サブスク」画面から解約できます。受取人は管理画面（/manage）から料金変更・即時解約・期間末の解約ができます。
  • subscription を省いて interval / intervalCount を直接書いても受け付けます。

状態を読む

GET/api/checkout/public/sessions/:id認証なし・CORS 許可
const res = await fetch(`https://karopay.karon.jp/api/checkout/public/sessions/${encodeURIComponent(id)}`);
const { ok, checkoutSession, error } = await res.json();

ID を知っている人なら誰でも読めます。期限を過ぎた open は、読んだ時点で expired に変わります。存在しない ID は 404 CHECKOUT_SESSION_NOT_FOUND。

Checkout オブジェクト

{
  "id": "kcs_xxxxxxxx",
  "checkoutUrl": "https://karopay.karon.jp/checkout/kcs_xxxxxxxx",
  "merchant": { "id": "site_...", "name": "受取人の名前", "mcid": "受取人のMCID" },
  "amount": 300,
  "description": "VIP Pass（毎月）",
  "mode": "subscription",                // "payment" | "subscription"
  "subscription": {                      // payment のときは null
    "id": "ksub_xxxxxxxx",               // 支払い後に入る。それまで null
    "interval": "month",
    "intervalCount": 1
  },
  "status": "paid",
  "successUrl": "https://example.com/success.html",
  "cancelUrl": "https://example.com/",
  "clientReferenceId": "order:12345",
  "payerName": "支払った人のMCID",        // 支払い後に入る
  "transferId": "...",                   // KaroPay 内の送金 ID
  "expiresAt": "2026-11-22T12:30:00.000Z",
  "paidAt": "2026-11-22T12:05:12.000Z",
  "canceledAt": null,
  "createdAt": "2026-11-22T12:00:00.000Z"
}
status意味
open支払い待ち。期限までは checkoutUrl から支払える。
paying処理中（ふつうは数秒で paid になる）。
paid支払い済み。お金は受取人の口座に入っている。
expired期限切れ。もう支払えない。
canceled受取人が取り消した（APIキー版）。

戻り先のクエリ

KaroPay は戻り先の URL に次のクエリを足します（もとのクエリは残ります）。

名前説明
checkout_session_idCheckout の ID（kcs_...）。
statussuccessUrl では paid、cancelUrl では canceled。
client_reference_id作るときに渡した注文番号（あれば）。
subscription_idサブスクの契約 ID（あれば）。
クエリの status=paid は誰でも手で書けます。これだけで商品を渡してはいけません。必ず GET で KaroPay に問い合わせてください。

支払いの確かめ方

商品を渡す前に、KaroPay から読んだ Checkout で次の 3 つを確かめます。

  1. status === "paid"
  2. amount が自分の注文の金額と同じ
  3. clientReferenceId が自分の注文番号と同じ（＝自分が作った Checkout）

サイト用コード版は、誰でも任意の金額で Checkout を作れます。安い Checkout を払って高い商品の注文番号を名乗る、といったことを防ぐため、金額と注文番号は自分の側の記録と照らします。同じ Checkout で 2 回渡さないよう、渡したことも記録してください。

ゲーム内のアイテムやランクを自動で渡すときは、ブラウザではなく自分のサーバー（またはアドオン・bot）で確かめてから渡してください。ブラウザの JavaScript は書き換えられます。このサンプルの success.html は表示のデモです。

APIキー版（サーバーから）

自分のサーバーから使う版です。APIキーは KaroEarth の運営が発行します（受取口座の MCID と表示名を決めて運営に頼んでください）。キーは秘密です。ブラウザのコードや公開リポジトリに入れないでください。

POST/api/checkout/sessionsBearer
const res = await fetch('https://karopay.karon.jp/api/checkout/sessions', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.KAROPAY_API_KEY}`,
    'Content-Type': 'application/json',
    'Idempotency-Key': orderId
  },
  body: JSON.stringify({
    amount: 500,
    description: 'VIP Rank',
    clientReferenceId: orderId,
    successUrl: 'https://example.com/thanks',
    cancelUrl: 'https://example.com/cart'
  })
});

パラメータはサイト用コード版と同じで、receiveCode は要りません（キーに結び付いた口座が受取人）。キーが無い・違うときは 401 UNAUTHORIZED。

GET/api/checkout/sessions/:idBearer

自分のキーで作った Checkout だけ読めます（ほかは 404）。

Idempotency-Key

ヘッダー Idempotency-Key（または本文の idempotencyKey。英数字と . _ : -、160 文字まで）を付けると、同じキーで送り直しても同じ Checkout を返します。通信が切れて再送しても二重に作られません。同じキーで中身の違う依頼を送ると 409 IDEMPOTENCY_KEY_REUSED。

取り消し

POST/api/checkout/sessions/:id/cancelBearer

open の Checkout を canceled にして、もう支払えないようにします。在庫切れや注文の取りやめに使います。open 以外は 400 CHECKOUT_SESSION_NOT_PAYABLE。支払い済みのお金を戻すのは返金です。

動く例: server-example/server.mjs（Node.js 18 以上・依存なし）。

決済リンク

KaroPay の管理画面（/manage）で「商品」と「料金」を作り、決済リンクを発行すると、https://karopay.karon.jp/pay/klink_... という固定の URL ができます。

  • 同じ URL を何度でも共有できます。開いた人ごとに、30 分有効な新しい Checkout が作られます。
  • サイトに置くときは <a href="https://karopay.karon.jp/pay/klink_..."> にするだけです。決済リンクの API は KaroPay 自身の画面用で、ほかのサイトからは呼べません（CORS なし・FORBIDDEN_ORIGIN）。
  • 決済リンクには戻り先がありません。支払いの確認は管理画面の「決済」で行います。
  • リンクを無効にするか、商品・料金をアーカイブすると新しい支払いを受け付けなくなります（既存の契約はそのまま）。

支払い後（契約・返金）

支払い後の管理は KaroPay の画面で行います（API キーでは操作できません）。

  • 受取人（/manage）: 売上の概要、決済の一覧、全額・一部の返金、サブスク加入者の一覧、料金・周期の変更（次回の請求から）、即時解約・期間末の解約、顧客ごとの集計、操作履歴。
  • 購入者（/subscriptions）: 加入中の契約、解約、支払い明細（返金された額も見える）。
  • 返金は受取人の残高から購入者へ戻します。返金しても契約は解約されません。

エラー

失敗すると { "ok": false, "error": "コード" } を返します。

コードHTTP意味
CODE_REQUIRED400receiveCode がない。
CODE_NOT_FOUND404サイト用コードが無効（再発行された、など）。
INVALID_AMOUNT400金額が整数でない・0 以下・上限超え。
INVALID_SUBSCRIPTION400周期が day/week/month 以外、または回数が 1〜12 の外。
INVALID_REQUEST400URL が http(s) でない・長すぎる、clientReferenceId / Idempotency-Key の文字が不正。
UNAUTHORIZED401APIキーがない・違う（APIキー版）。
CHECKOUT_SESSION_NOT_FOUND404Checkout がない（APIキー版では他人の Checkout も 404）。
CHECKOUT_SESSION_NOT_PAYABLE400取り消そうとした Checkout が open でない。
IDEMPOTENCY_KEY_REUSED409同じ Idempotency-Key で違う中身を送った。
RATE_LIMITED429送りすぎ。Retry-After（秒）待つ。
INTERNAL_ERROR500KaroPay 側の問題。少し待って再試行。

制限

  • Checkout の作成・取り消しは、送り元 IP・同じパスごとに 1 分 80 回まで。超えると 429。
  • リクエスト本文は 32 KB まで。
  • 金額の上限は 1 回 100,000,000。支払いは購入者の KaroPay（銀行）残高から行われ、足りなければ支払えません。
  • CORS が許されているのは /api/checkout/public/sessions とその下だけです。
