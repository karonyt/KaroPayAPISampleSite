ゲーム内アイテムの自動受け渡し

ランクやアイテムを自動で渡すときの、いちばん安全な形です。金額はサーバーが決め、APIキーで Checkout を作り、支払いはサーバーが KaroPay に問い合わせて確かめます。ブラウザは書き換えられるので、渡す判断をブラウザにさせません。動くサーバーの例は server-example/server.mjs にあります。

使う API: POST /api/checkout/sessions（Bearer・Idempotency-Key） / GET /api/checkout/sessions/:id / POST /api/checkout/sessions/:id/cancel ・ このページのソース

Code

サーバーの要点

// ② 注文を作る。Idempotency-Key = 注文 ID で、送り直しても二重にならない
const res = await fetch('https://karopay.karon.jp/api/checkout/sessions', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.KAROPAY_API_KEY}`,
    'Content-Type': 'application/json',
    'Idempotency-Key': order.id
  },
  body: JSON.stringify({
    amount: CATALOG[itemId].amount,          // ブラウザから金額を受け取らない
    description: CATALOG[itemId].name,
    clientReferenceId: order.id,
    successUrl: `${PUBLIC_URL}/thanks?order=${order.id}`,
    cancelUrl: `${PUBLIC_URL}/shop`
  })
});

// ⑤ 確かめてから ⑥ 渡す
const { checkoutSession: s } = await (await fetch(
  `https://karopay.karon.jp/api/checkout/sessions/${order.sessionId}`,
  { headers: { Authorization: `Bearer ${process.env.KAROPAY_API_KEY}` } }
)).json();

if (s.status === 'paid' && s.amount === order.amount && s.clientReferenceId === order.id) {
  // DB で「未配布 → 配布済み」を 1 回だけ切り替えられたときだけ渡す
  if (await db.markFulfilled(order.id)) await game.give(s.payerName, order.itemId);
}

全体は server-example/server.mjs（Node.js 18 以上・依存なし）。KAROPAY_API_KEY=... node server-example/server.mjs で動きます。

Without a key

APIキーがないとき

サイト用コード版（/api/checkout/public/...）でも、自分のサーバーから GET で状態を読めば同じ確かめ方ができます。違いは、誰でも Checkout を作れるので金額と注文番号の照合が必須になることと、Idempotency-Key と取り消しが使えないことです。

Points

実装のポイント

  • APIキーは KaroEarth の運営が発行します。キーはサーバーの環境変数に置き、ブラウザや公開リポジトリには入れません。
  • 注文 ID を Idempotency-Key にすると、通信が切れて送り直しても Checkout は 1 つだけです。
  • 渡す前に status === "paid"・金額・clientReferenceId の 3 つを確かめ、「渡した」を DB に記録して二重に渡さないようにします。
  • 購入者が戻ってこなくても渡せるよう、未完了の注文を定期的に読み直します（例: 1 分ごと、期限まで）。
  • 在庫切れなどで売れなくなったら、支払い前の Checkout を /cancel で取り消します。
